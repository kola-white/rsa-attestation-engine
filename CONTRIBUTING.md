# Contributing to Cvera

Thank you for your interest in Cvera API & Infrastructure V1.

## Scope

This repository provides the API and infrastructure foundations for verifiable claims and attestations.

Contributions should support the existing API, security, reproducible deployment, testing, and developer documentation.

Mobile application features, new authentication providers, hardware security module expansion, additional claim types, SDKs, and dashboards are outside the V1 release scope.

## Getting Started

1. Fork the repository and create a focused feature branch.
2. Review the README and existing developer documentation.
3. Follow the existing project conventions and configuration examples.
4. Keep production secrets and private keys outside the repository.
5. Run the relevant tests before submitting changes.

## Pull Requests

- Explain the purpose and scope of the change.
- Reference a related issue when applicable.
- Include tests for behavioral changes where practical.
- Update documentation when interfaces or deployment instructions change.
- Avoid unrelated refactoring and unnecessary dependencies.
- Ensure no credentials, private keys, or sensitive user information are included.

## Security Issues

Do not open public issues for security vulnerabilities. Follow [SECURITY.md](SECURITY.md) for private reporting.
