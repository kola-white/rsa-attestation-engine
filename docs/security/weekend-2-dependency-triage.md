# Weekend 2 dependency finding dispositions

Design follow-up to draft PR #130. This classifies the **existing 16 symbol-level findings**; it is not a fresh audit or scanner run. Original advisories, affected versions, tool configuration and example traces remain in [the saved results](weekend-2-vulnerability-results.json). No dependency or compiler was changed.

Classification meanings:

- **Prerequisite absent in inspected runtime:** the advisory's triggering protocol/profile/operation was not found in the configured application path. This is a scoped code/configuration disposition, not a declaration that the dependency is universally safe.
- **Configuration input only / not publicly demonstrated:** the observed dataflow does not take the triggering input from an API caller. Deployment secrets/settings were not inspected.
- **Applicable path; patch verification outstanding:** the application uses the affected facility under conditions relevant to the advisory. No exploit was run, and the release binary/compiler was not inspected.

Evidence reviewed beyond the saved results: the API server entrypoint, route registrations, explicit JSON binding call sites, SDK storage operations, issuer resolver/client construction, and exact cached dependency sources for pgx v5.8.0 and x/text v0.29.0. No exploit attempt, stress test, production configuration access or whole-repository reassessment was performed.

**Acceptance consequence:** eleven findings have absent protocol/operation prerequisites in the inspected runtime, one has an absent query-shape/protocol combination (5004), one has an absent PRECIS profile (6629), one has only configuration-controlled input demonstrated (5970), and two remain applicable paths pending actual release patch verification (6611 and 6809). This totals the existing 16 findings. These are technical dispositions for review, not automatic waivers. Enabling a previously absent protocol/operation requires revisiting the corresponding disposition.

The Dockerfile/CI still select Go 1.25 while the original scan used local Go 1.27.1. No compiler migration is implemented or silently assumed. Do not attribute host-standard-library findings to production without binary/build evidence, and do not certify a Go 1.25 release from this host scan. Selecting a supported patched compiler, proving the production-equivalent build and rerunning the relevant checker remain independent release work requiring compatibility verification. No dependency upgrade is justified solely to erase an overbroad error-interface trace.
